# Models

Nothing is bundled in the APK. The phone downloads what it needs once, over Wi-Fi, from the
first-run wizard, and then runs offline forever. `app/src/main/assets/models.json` is the
manifest that drives it.

## What ships in the manifest today

| Model | Role | Size | Licence | Digest verified |
|---|---|---|---|---|
| Silero VAD v6.2.3 | voice activity detection | 2.2 MB | MIT | yes |
| Parakeet TDT 0.6B v3 INT8 | speech recognition (25 languages incl. Russian, English) | 465 MB | CC-BY-4.0 | yes |

Two files, about 465 MB in total, both required.

**Upgrading from v2 (English only) has no gap.** The v2 files keep working until v3 has
downloaded and verified; the recorder then swaps engines without closing the microphone. There is no language model here: summaries are
generated by a hosted endpoint whose address and key are settings, so there is nothing to
download for them and no memory floor to meet. See the Summaries section of the README.

**Upgrading from 3.x leaves a 769 MB Gemma behind** in `files/models/llm/`. Nothing will ever
load it again. `ModelHealth.strayModelFiles` finds it and Settings → Recording → Speech models →
"Remove them" deletes it; the path is hard-coded there, since the runtime that owned it is gone.

Every URL and byte size above was checked against the source, not copied from a README:

```
silero_vad.onnx                   2,327,524  sha256 1a153a22…88e3
parakeet …v3-int8.tar.bz2       487,170,055  sha256 5793d0fd…16bf
```

Both shipped entries carry a real SHA-256, computed from the real download. The installer checks
size and digest, and refuses a file that fails either.

The section that used to live here explained why the GGUF language models shipped without a
digest — Hugging Face stores them as LFS objects whose hash was not reachable from the build
environment, and computing it meant downloading gigabytes. That trade is gone with the models.

## Adding a model by hand

```json
{
  "id": "some-model-q4",
  "role": "asr",
  "displayName": "Some Recogniser (INT8)",
  "fileName": "some-recogniser-int8.tar.bz2",
  "url": "https://…/some-recogniser-int8.tar.bz2",
  "revision": "main",
  "sizeBytes": 480000000,
  "sha256": "…64 hex chars…",
  "license": "Apache-2.0",
  "required": true,
  "archive": "tar.bz2",
  "hashVerified": true,
  "notes": "Shown to the user on the download screen."
}
```

Get the size and digest the same way the shipped ones were:

```bash
curl -sIL "<url>" | grep -i content-length
curl -sL "<url>" | sha256sum
```

Fields that matter:

- `role` — `vad` or `asr`. An unknown role is skipped, not fatal. There is no third role any
  more: the `small_chat` role and everything that read it went with the on-device model.
- `required` — the user cannot untick it, and setup is not "complete" without it. Both shipped
  entries are required.
- `archive` — `tar.bz2`, or null. Archives are unpacked into the role's directory, flattened,
  keeping only `*.onnx` and `tokens.txt`; entry paths are checked so a malformed archive
  cannot write outside the target directory.
- `sha256` — omit it rather than guessing. The installer then checks size only, and the UI
  tells the user the download was not checksum-verified.

`./gradlew :app:testRazrDebugUnitTest` validates the shipped manifest: well-formed digests,
https URLs, positive sizes, supported archive formats, and that a `hashVerified` entry
actually carries a hash.

## Where files land on the phone

| Role | Path (app-private) |
|---|---|
| `vad` | `files/models/silero_vad.onnx` |
| `asr` | `files/models/asr/` (encoder, decoder, joiner, tokens) |

App-private storage, so uninstalling the app removes the models, and nothing else on the
phone can read your transcripts or the models beside them.

## Developer fallback

`scripts/fetch_models.sh` still pushes models over ADB for development. It uses `run-as`,
which only works on a debuggable build, so point it at the debug applicationId:

```bash
PKG=com.recorder.app.debug ./scripts/fetch_models.sh --vad --asr
```
